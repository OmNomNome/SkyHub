# Задача для Opus 5.5

Ты — senior full-stack разработчик. Создай (или доработай, если приложен архив `SkyHub.zip`) полностью рабочую учебную информационную систему авиакомпании: расписание рейсов, пассажиры, билеты, багаж, карта рейсов. Работай автономно: пиши файлы, **запускай и проверяй** (seed, API, сборку фронтенда), чини ошибки, и только потом отдавай результат. Не говори «готово», пока не прогнал проверки из раздела 9.

Приложены: `airports.csv` (244 аэропорта России) и `terminals.csv` (87 терминалов). Положи их в `backend/data/`.

## 1. Среда и жёсткие ограничения
- Целевая ОС пользователя — Windows, Node.js 26 (очень новый). Запуск из одной папки `SkyHub/`, в т.ч. с флешки, без установки СУБД, без авторизации.
- Второй способ запуска — Docker (один контейнер, см. раздел 8). Docker не заменяет `start.bat`.
- Интерфейс, комментарии в ключевых местах, README — на русском.
- Код простой и читаемый, без лишних абстракций. Валидация на backend. Все ошибки API: `{ "error": "текст" }`, статусы 400/404/409.

## 2. Стек (строго, версии закрепить)
- Backend: Node.js + Express (CommonJS), Prisma **5.22.0** (`prisma` и `@prisma/client` ровно этой версии), SQLite (`database/app.db` в корне проекта).
- Frontend: React 18 + Vite 5, Ant Design 5, `react-calendar-timeline@0.28.0` (+ `moment`), axios, dayjs, `leaflet@^1.9.4` и `react-leaflet@^4.2.1`.
- Структура: `backend/{src,prisma,data}`, `frontend/src/{api,pages,components}`, `database/`, `start.bat`, `README.txt`, `Dockerfile`, `docker-compose.yml`, `.dockerignore`.
- Роуты и контроллеры можно держать в одном `routes.js`, бизнес-логику — в `services.js`. Компоненты `RoleSwitcher`, `GanttView`, `SeatMap`, `MapView` — отдельными файлами в `components/`.

## 3. Известные грабли (уже наступали — не повторять)
1. **`schema.prisma` пиши в обычном многострочном виде.** Однострочные модели `model X { a Int  b String }` Prisma не принимает (ошибка P1012).
2. Схема лежит в `backend/prisma/schema.prisma`, значит в `.env` путь должен быть `DATABASE_URL="file:../../database/app.db"` (Prisma считает путь от файла схемы). В Docker: `file:/data/app.db`.
3. SQLite + Prisma 5.22: enum не использовать, значения хранить строками и проверять на backend.
4. Перед запуском проверь, что `prisma db push` и `prisma db seed` реально проходят на чистой БД, а повторный запуск seed не ломает и не дублирует данные (seed пропускается, если в БД уже есть аэропорты; сообщение «для сброса удалите database\app.db»).
5. `react-calendar-timeline` не заявляет поддержку React 18: `npm install` во фронтенде ставить с `--legacy-peer-deps --no-audit --no-fund`, иначе установка идёт очень долго (в Docker — 6+ минут). Прописать флаг в `start.bat` и `Dockerfile` (в Dockerfile ещё кэш `--mount=type=cache,target=/root/.npm`).
6. В `start.bat` проверять наличие не папки `node_modules`, а конкретных пакетов (`backend\node_modules\express`, `frontend\node_modules\vite`), и после каждого шага проверять `errorlevel` (при ошибке — сообщение и `pause`, без запуска окон). Иначе оборванный `npm install` оставляет пустую папку, и бэкенд падает с «Cannot find module 'express'».
7. Призмовские команды в `start.bat` — через `npx --no-install prisma ...`, чтобы `npx` не скачивал другую версию Prisma. npm 11 предупреждает `install-scripts ... allowScripts` про `@prisma/client`, `prisma`, `@prisma/engines`: проверь, что postinstall отработал (`prisma generate` проходит); при необходимости добавь в README команду `npm install-scripts approve @prisma/client @prisma/engines prisma`.
8. `chcp 65001` и UTF-8 без BOM в `start.bat`; пути с пробелами — в кавычках.

## 4. Модель данных
- `Aircraft`: id, model (только `Boeing 737` или `Airbus A320`), tailNumber (уникальный, `RA-73001`), status (`READY|IN_FLIGHT|MAINTENANCE`), businessRows (по умолчанию 3), economyRows (по умолчанию 25). Салон 3+3, место `1A..1F`; бизнес — первые businessRows рядов.
- `Airport`: id, code (IATA, уникальный), name, city, latitude, longitude, timezone, size. Источник — `airports.csv` (поля `iata,name_ru,city_ru,latitude,longitude,timezone,size`; строки без `iata` пропускать, дубликаты iata отбросить).
- `Terminal`: id, airportId, name, purpose, flights (`all|domestic|international`). Источник — `terminals.csv` (`iata,terminal,purpose,flights`).
- `User`: id, fullName, role (`DISPATCHER|CHECKIN|BAGGAGE|ADMIN|PILOT|COPILOT|STEWARD`), phone, email.
- `RegularSchedule`: flightNumber, aircraftId, departureAirportId, arrivalAirportId, daysOfWeek (`"1,3,5"`, 1=Пн…7=Вс), departureTime (`HH:mm`), durationMinutes, validFrom, validTo.
- `Flight`: flightNumber, aircraftId, departureAirportId, arrivalAirportId, **departureTerminal, arrivalTerminal (строки, nullable)**, departureTime, arrivalTime, status (`SCHEDULED|CHECKIN_OPEN|DEPARTED|ARRIVED|CANCELLED`), isRegular, regularScheduleId.
- `FlightCrew`: flightId, userId, roleOnFlight. На рейс: 1 пилот + 1 второй пилот + 6 стюардесс.
- `Passenger`: fullName, passport (уникальный), phone, email.
- `Ticket`: ticketNumber (уникальный), passengerId, flightId, **seatNumber — nullable**, class (`BUSINESS|ECONOMY` — купленный класс), status (`BOOKED|CHECKED_IN|CANCELLED`).
- `Baggage`: ticketId, tagNumber (уникальный, `BAG-YYYY-NNNNNN`, генерируется на backend), weight, dimensions, type (`CARRY_ON|CHECKED`), status (`ACCEPTED|LOADED|DELIVERED|LOST`).

## 5. Роли и функции (одно SPA, выпадающий список роли в шапке, без логина)
**Диспетчер** (две вкладки/переключателя: «Диаграмма» и «Карта», фильтр «День/Неделя» + DatePicker):
- Диаграмма Ганта (`react-calendar-timeline`): строки — самолёты, блоки — рейсы, цвет по статусу. Блоки только для чтения (`canMove/canResize = false`), клик открывает окно рейса.
- **Читаемость недельного вида (исправление):** в режиме «Неделя» блок ≈10 px, текст налезал на соседние. Решение: блок с `overflow:hidden`, в недельном режиме внутри только номер рейса мелким шрифтом, полный текст — в `title`; диаграмма в режиме «Неделя» обёрнута в контейнер `overflowX:auto` с `minWidth ≈ 3500px`. В дневном режиме — полный текст с маршрутом.
- Создание рейса: разовый или регулярный (дни недели, время, период; шаблон разворачивается в конкретные `Flight`, конфликтные дни пропускаются и считаются). Самолёт — только `READY`. Аэропорты — `Select` с поиском (`showSearch optionFilterProp="label"`), их 200+.
- Проверки: борт не может иметь пересекающиеся рейсы; `MAINTENANCE` запрещён.
- Назначение экипажа (1+1+6) с проверкой конфликтов с буфером 1 час (учитывать время полёта); понятная ошибка с ФИО и номером рейса.
- Статусы: `SCHEDULED → CHECKIN_OPEN → DEPARTED → ARRIVED`, отмена из `SCHEDULED/CHECKIN_OPEN`. Недопустимые переходы — 409.
- В окне рейса показывать терминалы вылета/прилёта.
- **Карта (Leaflet, подложка OpenStreetMap, нужен интернет):** аэропорты — маркеры; маршруты — дуги большого круга (сегменты по ~32 точки), одинаковые маршруты сливать в одну линию с подсказкой «N рейсов»; самолёты «в воздухе» — маркер ✈ на дуге, положение считается по доле пройденного времени (`now` обновлять раз в 30 с); попап рейса. Счётчики над картой: маршрутов, рейсов за период, в воздухе сейчас. Рейсы берутся те же, что в Ганте (по выбранному периоду).

**Стойка регистрации:**
- Поиск по номеру билета, паспорту или ФИО.
- **Место выбирается ТОЛЬКО при регистрации (исправление).** У билета в статусе `BOOKED` места нет (`seatNumber = null`, в таблице «—»). Кнопка «Зарегистрировать» неактивна, пока место не выбрано. Backend: `PATCH /tickets/:id/checkin` обязательно требует `seatNumber` (иначе 400), проверяет существование места в салоне, занятость (409) и **соответствие класса билета зоне салона** (билет эконом → нельзя сесть в бизнес-ряд, и наоборот; 409). Класс билета при регистрации не меняется. Допустимо менять место уже зарегистрированному.
- Интерактивная схема салона 3+3: бизнес и эконом разных цветов, занятые и «чужого класса» места недоступны (затемнены), выбранное — зелёное.
- Багаж: тип, вес, габариты → автогенерация бирки, кнопка «Показать бирку» (модалка с крупным номером, «Печать»). Перевес (ручная кладь > 10 кг, регистрируемый > 23 кг) — жёлтый Alert и предупреждение, но оформление не блокируется.

**Багажное отделение:** список с фильтрами (рейс — с поиском, статус, бирка); переходы `ACCEPTED → LOADED → DELIVERED`, `LOST` — из `ACCEPTED/LOADED`.

**Администратор:** CRUD самолётов (запрет удаления при связанных рейсах, смена статуса), аэропортов (с широтой/долготой), пользователей (включая экипаж); read-only с поиском: пассажиры, билеты (колонки «Место» и «Класс»), терминалы.

## 6. Данные seed (много, детерминированно — ГПСЧ с фиксированным seed)
- Аэропорты и терминалы — целиком из CSV (≈240 и ≈87).
- Самолёты — 22 (чередовать Boeing 737 / Airbus A320, `RA-73001…`), у части разное число эконом-рядов.
- Сотрудники: 3 диспетчера, 4 стойки, 4 багаж, 1 админ, **26 пилотов, 26 вторых пилотов, 140 стюардесс** (есть свободные сверх бригад — для демонстрации конфликтов).
- Регулярные рейсы: у каждого из 20 бортов пара «туда-обратно» от хаба (SVO, SVO, LED, KZN, OVB, AER по кругу) до случайного крупного аэропорта на расстоянии 500–4500 км; длительность ≈ расстояние/750 км/ч + 30 мин; обратный рейс вылетает через 90 мин после прилёта; разные шаблоны дней недели; период от «сегодня−2» до «сегодня+13». Номера `SU1000+`. Плюс 2 разовых рейса на завтра на свободных бортах (`SU9001`, `SU9002`).
- Терминалы рейсов выбирать из терминалов аэропорта с `flights ≠ international`.
- Статусы рейсов проставлять по текущему времени: прилетел → `ARRIVED`, в пути → `DEPARTED`, вылет в ближайшие 3 часа → `CHECKIN_OPEN`, иначе `SCHEDULED`.
- Экипаж: у борта i — своя бригада (пилот i, второй пилот i, стюардессы i*6..i*6+6), назначается на ~3 из 4 рейсов этого борта (остальные без экипажа — для демо). Конфликтов в seed быть не должно.
- Пассажиры — 800, уникальные паспорта, реалистичные ФИО (согласовать род фамилии/имени/отчества).
- Билеты ≈ 4–11 на рейс (≈3500+). Сначала нумеровать билеты будущих рейсов. **У `BOOKED` места нет; у `CHECKED_IN` — случайное свободное место нужного класса, без повторов на рейсе.** Вероятность регистрации: 10% для `SCHEDULED`, 85% для остальных; класс 12% бизнес. **Билет `TK100001` обязан быть `BOOKED` на будущем рейсе — по нему идёт демо.**
- Багаж у ~60% зарегистрированных, ≈8% с перевесом, статус по статусу рейса (`ARRIVED`→`DELIVERED`, `DEPARTED`→`LOADED`, иначе `ACCEPTED`, ~1% `LOST`). Бирки `BAG-YYYY-NNNNNN` подряд (генератор: max(id)+1).
- Для скорости использовать `createMany` пачками по 500 и `$transaction` для массовых update.
- Seed должен читать CSV сам (парсер с кавычками, BOM, `\r\n`), чтобы пользователь мог заменить файлы.

## 7. start.bat и README.txt
`start.bat`: проверка Node → `mkdir database` → установка зависимостей по правилам из п. 3 → `npx --no-install prisma db push` → `npx --no-install prisma db seed` → два окна (`start "Backend"` и `start "Frontend"`) → пауза 6 с → браузер `http://localhost:5173`. Backend: `http://localhost:3000`, Vite проксирует `/api` на него. README.txt (кратко): запуск, адреса, роли, сброс БД (удалить `database\app.db`), заметка, что карте нужен интернет, демо-сценарий:
1. Админ: борт → `MAINTENANCE`, убедиться, что в создании рейса его нет, вернуть `READY`.
2. Диспетчер: создать регулярный рейс SVO→LED пн/ср/пт, увидеть на Ганте и на карте; назначить экипаж; назначить того же пилота на пересекающийся рейс → ошибка.
3. Стойка: найти `TK100001` (места нет), выбрать место на схеме → зарегистрировать; багаж 30 кг → предупреждение + бирка.
4. Багаж: найти по бирке, `ACCEPTED → LOADED`.
5. Диспетчер: рейс → `DEPARTED` → `ARRIVED`; на карте виден самолёт в воздухе.

## 8. Docker
Один контейнер: многостадийный `Dockerfile` (`node:20-bookworm-slim`): стадия 1 собирает фронтенд (`vite build`), стадия 2 — backend + `openssl` (нужен Prisma) + готовая статика в `backend/public`. Express отдаёт статику (`express.static`) и API на `:3000`. `DATABASE_URL=file:/data/app.db`, том `skyhub_data:/data`. `CMD`: `prisma db push --skip-generate && prisma db seed && node src/index.js`. `docker-compose.yml` с портом `3000:3000` и томом; `.dockerignore`: `**/node_modules`, `backend/.env`, `database`. При смене схемы старую БД нужно сбросить: `docker compose down -v`.
