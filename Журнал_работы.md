# Журнал работы — SkyHub

SkyHub — учебная информационная система авиакомпании: расписание рейсов, пассажиры, билеты, багаж и карта рейсов.
Полное техническое задание лежит в файле `ТЗ.md`.

## План (делаем по этапам)

1. Переименование проекта и подготовка папки ✅
2. Бэкенд: схема Prisma, seed, API (Express)
3. Проверка бэкенда curl-запросами
4. Фронтенд: роли, диаграмма Ганта, карта, схема салона
5. start.bat, README.txt, Docker
6. Финальные проверки и архив `SkyHub.zip`

## 2026-11-17 — Этап 1.1. Исходные данные

**Что сделано:**
- `airports.csv` и `terminals.csv` скопированы из папки «Загрузки» в `backend/data/`.
- Проверено, что лежит в файлах:
  - `airports.csv`: 244 строки данных и 22 колонки, это больше, чем указано в ТЗ. Нужные колонки (`iata, name_ru, city_ru, latitude, longitude, timezone, size`) есть. Файл начинается с BOM. Размеры аэропортов: large 45, medium 114, small 85. У 30 строк нет кода `iata`, поэтому после фильтра останется около 214 аэропортов, а не 240.
  - `terminals.csv`: 87 строк, колонки `iata, terminal, purpose, flights` плюс служебные `source_url, checked_at`.
- Окружение: Node.js v26.12.1, npm 11.20.0. Это совпадает с ТЗ.

**Почему так:**
- Парсер в seed будет искать колонки **по имени заголовка**, а не по номеру. Поэтому лишние колонки ему не мешают, и пользователь сможет подложить файл с другим порядком колонок.
- Строки без `iata` пропускаем по ТЗ: без кода аэропорт нельзя использовать в рейсах, потому что код уникальный.

## 2026-11-17 — Этап 1.2. Git и бэкап на GitHub

**Что сделано:**
- Создан локальный git-репозиторий, ветка `main`.
- Автор коммитов задан **только для этого проекта** (`git config` без `--global`): имя `OmNomNome`, почта — скрытая почта GitHub `...@users.noreply.github.com`.
- Добавлен `.gitignore`: в репозиторий не попадают `node_modules`, база `database/`, `.env`, сборка фронтенда и архив `SkyHub.zip`.
- Создан **публичный** репозиторий https://github.com/OmNomNome/SkyHub, туда отправлен первый коммит.

**Правило бэкапа:** после каждой завершённой подзадачи делаю коммит с понятным описанием и `git push` на GitHub.

**Почему так:**
- Скрытая почта (noreply) нужна, чтобы коммиты привязывались к аккаунту GitHub, а настоящий адрес не был виден всем в публичном репозитории.
- Настройка только для этого проекта, а не глобальная, потому что она не трогает систему за пределами `C:\claude_main_rep`.
- `node_modules` и базу не коммитим: их можно восстановить командами `npm install` и `prisma db push && prisma db seed`, а в репозитории они только раздувают размер.
- Утилиты `gh` (GitHub CLI) на компьютере нет. Репозиторий создан через подключённый к Claude коннектор GitHub, а отправка изменений идёт обычным `git push`. При первой отправке Git Credential Manager открывает браузер для входа в GitHub.
- Вопрос на потом: `.env` в репозиторий не попадает. Чтобы проект запускался сразу после `git clone`, на этапе бэкенда сделаем так, чтобы `start.bat` создавал `.env` сам, если файла нет. Секретов там нет, только путь к базе.
